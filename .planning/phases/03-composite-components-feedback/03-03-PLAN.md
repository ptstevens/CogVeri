2. Create `frontend/src/components/ui/composites/FormField/FormField.tsx`:

FormField wraps any form input child with consistent label + error + helpText layout.
It supports validation hooks that auto-display errors via onBlur validation.

Props interface:
```typescript
interface FormFieldProps {
  label: string;
  error?: string;
  helpText?: string;
  required?: boolean;
  children: React.ReactElement;
  className?: string;
  // Validation hook support - auto-displays errors on blur
  onBlur?: () => void;
  validate?: () => string | undefined; // Returns error message or undefined
}
```

Implementation:
- Use `useId()` hook to generate unique IDs
- Use `useState` to track `touched` state (set true onBlur)
- Clone child element to inject:
  - `id` for label association
  - `aria-invalid={!!error}`
  - `aria-describedby` pointing to error or helpText element
  - `onBlur` handler that:
    1. Sets touched = true
    2. Calls validate() if provided, updates internal error state
    3. Calls passed onBlur prop if provided
- Only show error when field is touched OR error prop is explicitly provided
- Layout:
  - Label: `block text-sm font-medium text-gray-700 mb-1.5`
  - Child input (cloned with props)
  - Error (if present AND touched): `text-sm text-error mt-1.5` with `role="alert"`
  - HelpText (if no error): `text-sm text-gray-500 mt-1.5`

Validation patterns supported:
```tsx
// Pattern 1: External error (react-hook-form, manual state)
<FormField label="Email" error={errors.email}>
  <Input type="email" {...register('email')} />
</FormField>

// Pattern 2: onBlur validation hook (auto-display on blur)
<FormField
  label="Email"
  validate={() => !email.includes('@') ? 'Invalid email' : undefined}
>
  <Input type="email" value={email} onChange={e => setEmail(e.target.value)} />
</FormField>
```

3. Create `frontend/src/components/ui/composites/FormField/index.ts`:
   - Export FormField and FormFieldProps

Note: This complements Input's built-in label/error props for cases where:
- Wrapping Select or Checkbox (which don't have built-in label handling)
- Consistent styling across different input types
- Integration with form libraries that provide error state separately
- Auto-validation on blur without form library

Important:
- Use design tokens for error color (text-error, not text-red-500)
- Support both Input (which has its own label) and Select/Checkbox
- When wrapping Input, user can omit Input's label prop to avoid duplication
- Touched state prevents showing errors before user interacts

Props interface:
```typescript
interface DropdownOption {
  id: string;
  label: string;
}

interface DropdownProps {
  options: DropdownOption[];
  value?: string;
  onChange: (value: string) => void;
  placeholder?: string;
  disabled?: boolean;
  error?: boolean;
  className?: string;
}
```

Implementation using useCombobox:
```typescript
const {
  isOpen,
  getMenuProps,
  getInputProps,
  getItemProps,
  highlightedIndex,
  selectedItem,
} = useCombobox({
  items: filteredOptions,
  itemToString: (item) => item?.label || '',
  selectedItem: options.find(opt => opt.id === value) || null,
  onSelectedItemChange: ({ selectedItem }) => {
    if (selectedItem) onChange(selectedItem.id);
  },
  onInputValueChange: ({ inputValue }) => {
    setInputValue(inputValue || '');
  },
});
```

Filtering:
- Filter options based on inputValue (case-insensitive)
- Show all options when input is empty or matches exactly

Styling:
- Input: Match Input primitive styling from CVA (border, focus ring, etc.)
- Dropdown menu: `absolute z-10 w-full mt-1 bg-white border rounded-lg shadow-lg max-h-60 overflow-auto`
- Menu items: `px-4 py-2 cursor-pointer`
- Highlighted item: `bg-primary-50`
- Selected item: `font-semibold`

Keyboard handling (provided by downshift):
- Arrow Up/Down: Navigate options
- Enter: Select highlighted option
- Escape: Close dropdown
- Type to filter

Accessibility (provided by downshift):
- ARIA combobox roles
- aria-expanded, aria-activedescendant

Implementation:

- Apply sizing based on size prop:

  - lg: `w-32 h-32`

- Wrap illustration in a container div for consistent spacing

Rendering logic:
```tsx
{illustration ? (
  <div className={cn('mx-auto', illustrationSizeClasses[size])}>
    {illustration}
  </div>
) : icon ? (
  <Icon className={cn('mx-auto', iconSizeClasses[size], 'text-gray-400')} />
) : null}
```

Usage example:
```tsx
<EmptyState
  illustration={<NoTasksIllustration className="w-full h-full" />}

/>
```
